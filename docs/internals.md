# lolterm 구현 상세

이 문서는 README에서 옮긴 구현 기록입니다. 최신 사용법과 UI는 [README](../README.md)를 먼저 읽으세요.

이스포츠 경기를 터미널에서 보는 싱글 바이너리 CLI. 명령은 `lolterm <게임> <명령>` 구조이며,
현재 지원하는 게임은 League of Legends(`lol`)다.

`lol` 은 프로 대회(MSI, Worlds, LCK, LPL, LEC, LCS 등)의 일정·결과·**실시간 인게임 보드**와 **지난 경기 다시 보기(replay)** 를 보여 준다.
lolesports.com 이 쓰는 비공식 엔드포인트를 그대로 사용한다. API 키는 사이트에
하드코딩된 공용 키이므로 별도 발급/설정 불필요.

## 설치

> 에이전트가 자동으로 세팅하려면 **[INSTALL.md](../INSTALL.md)** 를 그대로 따르게 하면 된다
> (사전 점검, PATH, 터미널 설정, 검증 체크리스트, 문제 해결 포함).

```bash
go install github.com/m16khb-org/lolterm@latest   # $(go env GOPATH)/bin 이 PATH 에 있어야 함
```

소스에서 빌드: `go build -o ~/.local/bin/lolterm .` — 자세한 절차는 [INSTALL.md](../INSTALL.md).

의존성 없음 (Go 표준 라이브러리만 사용). 외부 도구도 필요 없다.

## 사용법

인자 없이 실행하면 키보드만으로 쓰는 **대화형 앱**이 열린다. 리그, 경기, 세트, 폴링 간격을
모두 화살표 키와 Enter 로 고른다. 스크립트용 하위 명령은 그대로 남아 있다.

```
lolterm                      대화형 앱 (lolterm lol 도 같다)
lolterm <game> <command> [flags]
lolterm help                 지원 게임 목록
lolterm <game> help          게임별 명령 목록
```

## 대화형 앱

lazygit 처럼 번호가 붙은 테두리 창으로 구성된다. 왼쪽에 `[1] Leagues`, `[2] Matches`, `[3] Games` 목록이 쌓이고,
오른쪽 `[0]` 창은 선택한 경기의 미리보기(팀, BO, 점수, KST 시작 시각, Enter 를 누르면 일어날 일)나
실행 중인 보드를 보여 준다. 포커스가 있는 창은 초록색 굵은 테두리로 표시되고, 맨 아래 줄에 현재 문맥의 키가 나온다.

- **Leagues**: 모든 리그. worlds, msi, lck, lpl, lec, lcs 가 맨 위에 오고 나머지가 뒤따른다.
- **Matches**: `Live` / `Upcoming` / `Recent` 탭(`[` `]` 로 전환). 시각은 KST. 목록 끝에서 `PgDn` 을 누르면 더 오래된(Upcoming 은 더 먼 미래의) 경기를 불러온다.
- **Games**: 선택한 경기의 세트 목록(번호, 상태).
- Enter: 진행 중인 경기는 **라이브 보드**, 끝난 경기나 세트는 **replay 보드**를 `[0]` 창에서 연다. 시작 전 경기는 시작 시각 안내만 나온다.

| 키 | 동작 |
|---|---|
| `j` `k` / `↑` `↓` | 목록 이동 |
| `PgUp` `PgDn` / `g` `G` | 페이지 이동 / 처음·끝 (Matches 끝에서 `PgDn` = 더 불러오기) |
| `h` `l` / `←` `→` | 이전·다음 창 |
| `Tab` `Shift+Tab` / `1` `2` `3` `0` | 창 포커스 이동 (`0` = 오른쪽 메인 창) |
| `[` `]` | Matches 탭 전환 (Live / Upcoming / Recent) |
| `Enter` | 열기 (리그 → 경기 목록, 경기·세트 → 보드) |
| `r` | 선택한 리그의 경기 목록 다시 불러오기 |
| `Esc` | 뒤로: 팝업 닫기 → 확대 해제 → 목록으로 포커스 이동 → 보드 닫기 |
| `,` | 옵션 메뉴 (어디서나) |
| `?` | 현재 문맥의 키 도움말 |
| `q` / `Ctrl+C` | 종료 |

보드가 열려 있고 `[0]` 창에 포커스가 있을 때는 키가 보드로 간다.

| 키 | 보드 동작 |
|---|---|
| `Space` | replay: 일시정지 / 재생 |
| `←` `→` | replay: ±10초 이동 |
| `+` `-` | replay: 배속 1× → 2× → 4× |
| `b` | stats → items → runes 보기 전환 |
| `s` `o` | 골드 차이 스파크라인 / 오브젝트 맵 |
| `f` | 보드를 화면 전체로 확대(토글). `Esc` 로 되돌린다 |

옵션 메뉴(`,`)는 위아래 키로 항목을 고르고 Enter(또는 `←` `→`)로 값을 바꾼다. 바꾼 값은 바로 적용되며 `Esc` 로 닫는다.

| 항목 | 값 |
|---|---|
| Poll interval | 2s / 5s / 10s (실행 중인 라이브 보드는 새 간격으로 다시 시작) |
| Left column in board view | shown / hidden (hidden 이면 보드에 포커스가 있는 동안 목록을 숨긴다) |
| Language | en / ko / zh |

반응형: 너비 120칸 이상이면 왼쪽 열이 전체의 약 30%(최소 28, 최대 44칸), 80~119칸이면 26칸이다.
너비가 80칸 미만이거나 높이가 24줄 미만이면, 보드에 포커스가 있는 동안 왼쪽 열이 사라지고 보드가 화면 전체를 쓴다.
`Esc` 를 누르면 목록이 나타난다. 터미널 크기를 바꾸면 곧바로 다시 배치한다.

replay 보드 맨 아래 줄은 플레이어 바(재생 위치/전체, 배속, 일시정지)다. 헤더는 `REPLAY`,
푸터는 위치/전체 길이, 배속, 원래 경기 시작 시각(KST)을 보여 준다. 시리즈 점수(`[3]`)는 getEventDetails 가 최종 점수만 주기 때문에
경기의 마지막 세트를 볼 때만 표시되고, 앞선 세트에서는 `[-]` 이다.

### lol (League of Legends)

```
lolterm lol relay      [-l <league>] [-i Dur] [-1]   풀스크린 ASCII 실시간 중계 (0.5초 재생, 피드 폴링 -i)
lolterm lol replay     [-match ID [-g N]] [-l <league>]
                                                    끝난 경기 다시 보기: livestats 피드로 재생
                                                    (-match 없이 실행하면 최근 종료 경기 목록과 id)
lolterm lol live       [-l <league>] [-w]            실시간 경기 + 인게임 보드
lolterm lol streams    [-l <league>]                 중계 스트림 링크
lolterm lol standings  [-l <league>]                 대회 브래킷 / 순위
lolterm lol schedule   [-l <league>] [-n N] [-a]     다가오는 경기 (-a = 최근 결과)
lolterm lol leagues                                  리그 슬러그/ID 목록
lolterm lol demo       [-w N] [-h N] [-b|-r] [-s] [-o]
                                                    합성 보드 한 프레임 (네트워크 없음, 터미널 점검)
lolterm lol bench      [-w N] [-h N]                 풀 리페인트와 1초 diff 의 바이트 비용 비교
```

플래그
- `-l <league>`  리그 슬러그 필터 (`msi`, `worlds`, `lck`, `lpl`, `lec`, `lcs`, ...)
- `-w`           live: watch 모드, 30초마다 새로고침 (demo/bench 에서는 `-w N` 이 터미널 폭 지정)
- `-1`           relay: 단일 프레임만 출력 후 종료 (스크린샷/스크립트용)
- `-i Dur`       relay: 피드 폴링 간격 (기본 `2s`). 화면은 항상 0.5초 간격으로 갱신된다
- `-match ID`    replay: lolesports 경기 id (목록: `lolterm lol replay`)
- `-g N`         replay: 경기 안의 세트 번호 (기본 1)
- `-n N`         schedule: 표시할 경기 수 (기본 15)
- `-a`           schedule: upcoming 대신 최근/종료 경기
- `-w N` `-h N`  demo/bench: 터미널 폭·높이 지정 (0 = 자동)
- `-b` `-r` `-s` `-o` demo: items 보기 / runes 보기 / 골드 스파크라인 / 오브젝트 맵

## 예시

```bash
lolterm                           # 대화형 앱 (리그 → 경기 → 세트를 키보드로 선택)
lolterm lol replay                # 최근 종료 경기와 -match 에 쓸 id 목록
lolterm lol replay -match 115660588583040710 -g 1   # Worlds 2026 MVK vs FUR 1세트 다시 보기
lolterm lol relay -l msi          # MSI 풀스크린 실시간 중계 (0.5초 갱신, Ctrl+C 종료)
lolterm lol relay -1              # 단일 프레임만 캡처 (미리보기)
lolterm lol demo                  # 라이브 게임 없이 중계 화면 미리보기
lolterm lol live -l msi -w        # MSI 실시간 보드를 30초 간격으로 갱신
lolterm lol schedule -l lck -n 10 # LCK 다음 10경기
lolterm lol schedule -a -n 8      # 모든 리그 최근 결과
lolterm lol leagues               # 전체 리그 슬러그 확인
```

## 반응형 (responsive)

터미널 **너비와 높이**를 모두 감지해 자동으로 레이아웃을 바꾼다.

- **너비**: 좁아지면 선수 컬럼을 우선순위대로 드롭한다
  (HP숫자 → CS → 챔프 축소 → 이름 축소 → HP바 …). 최소 ~50컬럼까지 동작.
  104컬럼 이상에서는 **양 팀을 좌우 2단**으로 배치해 화면을 넓게 쓴다.
- **높이**: 28줄 이하면 **compact 모드**로 섹션 사이 빈 줄을 없애 줄 수를 줄인다.
  좁고 짧은 터미널에서도 테두리가 깨지지 않게 모든 줄 폭을 정확히 맞춘다.
- 킬/골드 비례 바, 오브젝트 행, 팀명도 가용 폭에 맞춰 자동 적응.

레이아웃 미리보기(임의 크기 지정):
```bash
lolterm lol demo -w 120        # 넓은 화면(좌우 2단) 미리보기
lolterm lol demo -w 60 -h 20   # 좁고 낮은 터미널 미리보기
```

## replay (지난 경기 다시 보기)

`lolterm lol replay -match <id> [-g N]` 은 끝난 세트를 relay 와 같은 보드로 되감아 보여 준다. 대화형 앱에서 Enter 로 여는 보드와 같은 엔진이다.
재생은 livestats 피드만 쓴다. 영상은 받지 않는다.

- 점수판은 livestats 프레임을 재생 위치(게임 시각)에 맞춰 보여 주고, 위치에서 먼 구간은 필요할 때 받아 온다(아래 "다시 보기 저장소").
- 부활 카운트다운은 전체 프레임을 가지고 있으므로 추정이 아니라 피드에서 읽은 정확한 시각이다(아래 "사망과 부활").
- 키: `Space` 일시정지, `←` `→` ±10초, `+` `-` 배속(1×/2×/4×), `b` `s` `o` 는 relay 와 같고, `q` 로 종료한다.

## 토글로 여는 디테일 (relay 실행 중 키 입력)

`lolterm lol relay` 실행 중 누르면 해당 패널이 열리고 다시 누르면 닫힌다
(diff 렌더러가 바뀐 부분만 갱신).

| 키 | 보기 |
|---|---|
| `b` (또는 Tab) | 뷰 **사이클**: stats → items(아이템 풀네임) → runes(룬 페이지 전체) → stats |
| `s` | **골드 차이 스파크라인** (관전 시작 후 누적, 시간별 청/적 리드) |
| `o` | **오브젝트 맵**: 타워 비례바·용 원소+소울·바론/억제/골드 리드 |
| `q` (Ctrl+C) | 종료 |

> 드래곤 4번째 팀은 기본 보드의 `DRG` 옆에 `★SOUL` 로 표시된다. 용·바론이 나오는 시각은 그 아래 줄에 보인다(아래 "오브젝트 타이머").
> 아이템/룬 이름은 `staticdata.go` 에 내장한 표(Community Dragon 에서 생성)를 쓴다. 네트워크에서 받아 오지 않는다.

## relay (실시간 중계)

`lolterm lol relay` 는 터미널 전체를 쓰는 풀스크린 중계 화면이다.

- **0.5초 재생**: 피드는 백그라운드에서 병렬(window+details 동시)로 받아 두고, 화면은 네트워크를 건드리지 않고
  버퍼에 쌓인 프레임을 0.5초 간격으로 재생한다. 한 번의 window 응답에는 10초 분량(실측 50~64프레임, 간격 불규칙)이 들어 있다.
  폴링 간격은 `-i`(기본 2초)이고, 재생 지연은 최근 수신 지연에 맞춰 자동 조절된다(아래 "재생 지연").
- 킬/골드는 비례 바(청팀 cyan / 적팀 red), 오브젝트(DRG/BRN/TWR/INB) 카운트,
  선수별 KDA·CS·골드·**HP바(체력에 따라 녹/황/적색)** 표시.
- 팀은 피드의 `blueTeamMetadata.esportsTeamId` 로 정해 블루 팀을 왼쪽에 놓는다. `getLive` 가 주는 팀 순서는 시리즈 내내 고정이라 세트마다 진영이 바뀌어도 그대로이기 때문이다.
- alt screen + 커서 숨김 사용. `Ctrl+C` 로 종료하면 터미널이 원래대로 복구된다.
- 게임 id 는 폴링 3회마다(약 30초) 재탐색해 세트 전환(다음 게임 시작)을 자동으로 따라간다.
- 터미널 너비를 자동 감지해 70~120 컬럼에 맞춘다.

> 참고: Riot 중계 feed는 게임이 실제로 중계(spectate)되기 시작해야 프레임이 밀려온다.
> 스케줄이 inProgress 라도 방송 시작 전엔 데이터가 비어오며, 그땐 `waiting for in-game data…`
> 로 표시된다. 이건 정상 동작이다.

## 재생 지연

피드의 프레임은 실제 시각보다 늦게 도착하므로 화면은 현재 시각이 아니라 조금 뒤의 프레임을 보여 준다.

- 지연 = 최근 8번 폴링의 수신 지연(받은 시각 − 최신 프레임의 타임스탬프) 중 최댓값 + 폴링 간격 + 0.5초 여유. 지연은 새 폴링마다 다시 계산한다.
- 일시정지 프레임을 받은 뒤의 침묵은 수신 지연으로 세지 않는다. 피드가 일부러 조용한 것이므로, 세면 재개 뒤에도 그 시간만큼 재생이 늦어진다.
- 처음에는 현재 시각에서 10초 단위로 뒤로 내려가며(최대 18단계, 약 3분) 프레임이 있는 가장 최근 구간을 찾는다. 가장 새 프레임이 3분보다 오래되면 같은 방식으로 다시 찾는다.

## 게임 시계와 일시정지

보드 헤더의 게임 시계는 `스폰 이후 피드 시각 − 3.5초 − 일시정지 누계` 다. 피드의 타임스탬프는 실제 시각이고 게임이 멈춰도 계속 흐르므로 일시정지 구간을 빼야 한다.
3.5초는 피드와 게임 시계의 고정 시차(코드의 `feedSkew`)다. 사망·오브젝트 계산도 같은 시계를 쓴다.

- **일시정지 찾기**: 피드가 `paused` 프레임을 내고 그 뒤 1.5초가 넘게 프레임이 없으면, 그 빈 구간이 일시정지다. 라이브는 폴링마다, replay 는 프레임을 받을 때마다 찾는다.
- **보드를 늦게 열었을 때**: 피드 버퍼(최근 5분)에는 그 전의 일시정지가 없다. 그래서 피드는 게임마다 한 번, 첫 폴링에서
  게임 시작부터 버퍼 시작까지의 10초 창을 모두 읽어(4개씩 동시에, 게임 34분째에 열면 203개·약 10초) 일시정지를 찾는다. 이것이
  없으면 헤더 시계와 오브젝트 타이머가 일시정지 길이만큼 앞선다. 일시정지가 5분보다 길면 그 시각이 버퍼 밖이라 이 조회가 없던 때의 보드는
  `waiting for in-game data…` 에서 멈췄다(2026 Worlds 8강 T1-KC 3세트, 6분 46초 일시정지 뒤에 연 보드). 조회가 실패하면 2분 뒤 다시 시도하고,
  경기를 처음부터 따라간 보드는 조회하지 않는다.
- **replay**: 게임 전체를 순서대로 받는 중에 일시정지도 함께 드러난다(아래 "다시 보기 저장소"). 아직 받지 못한 구간의 일시정지는 받은 뒤에 반영된다.

## 사망과 부활

보드의 선수 행 HP 칸에는 사망한 선수의 `☠ 23s` 가 나온다. 실시간 추정이면 `☠ ~23s` 다.
피드는 부활 시각을 주지 않는다. 사망은 피드의 deaths 카운트와 체력으로 읽는다.

- **사망**: deaths 카운트가 오른 프레임이 사망이다. 카운트는 체력이 0이 되기 약 0.5초 앞서 오른다(중앙값 0.52초). 사망 순간에서 부활까지를 그만큼 늦춰 센다. 카운트만 오르고 체력이 떨어지지 않으면(8초 안에) 사망이 아니라 되살아남이다.
- **부활(replay)**: 게임 전체 프레임이 있으므로, 체력이 떨어진 뒤 처음 절반 이상으로 돌아온 프레임이 부활이다. 정확하다. 아직 받지 못한 구간이 부활을 가리면 아래 추정을 쓴다.
- **부활(라이브)**: 레벨 L, 게임 T분에 죽은 선수는 `base[L] × (1 + 시간 계수(T))` 초 뒤에 돌아온다고 추정한다. 이 숫자들이 모델의 전부이고 피드에서 부활이 잡히면(체력 회복) 바로 맞춘다.
  - 기본 부활 시간(초), 레벨 1~18: 10, 10, 12, 12, 14, 16, 20, 25, 28, 32.5, 35, 37.5, 40, 42.5, 45, 47.5, 50, 52.5.
  - 시간 계수: 15분부터 분당 +0.85%, 30분부터 분당 +0.60%, 45분부터 분당 +2.9%, 최대 +50%.
  - 26게임 713회 사망으로 맞췄고 오차는 중앙값 0.24초, 전부 1.5초 안이다.
- **제자리 되살아남**: 사망 타이머보다 2초 넘게 일찍 체력이 돌아오면 부활이 아니라 제자리 되살아남(사이온의 `Glory in Death`, 피드가 좀비 체력통을 보여 준다)으로 보고, 다시 쓰러진 뒤 타이머 시각의 체력 회복을 부활로 본다.
- 프레임 사이가 3초를 넘게 비어 있으면(일시정지 제외) 아직 받지 못한 구간으로 보고 그 너머의 프레임으로 부활을 단정하지 않는다.

## 오브젝트 타이머 (용·엘더·바론)

보드의 오브젝트 행 아래에 용 구덩이와 바론 구덩이가 언제 나오는지 한 줄로 보여 준다. 라이브와 replay 모두 같은 계산을 쓰고, 일시정지와 탐색(←/→)도 그대로 따라간다.

```text
DRG 2 ── 4 ★SOUL     BRN 0 ── 1     TWR 4 ── 7     INB 0 ── 1
Dragon 3:12 Infernal · Baron UP · Soul point blue
```

- `3:12` 는 남은 시간, `UP` 은 구덩이에 살아 있다는 뜻, `--` 는 시각을 알 수 없다는 뜻이다. 좁은 터미널에서는 `DRG 3:12 INF · BRN UP`, 더 좁으면 `D 3:12 · B UP` 으로 줄어든다. 소울을 얻은 팀이 있으면 구덩이 이름이 `Elder` 로 바뀐다.
- 시각은 피드에서 팀의 `dragons` 목록이나 `barons` 수가 늘어난 첫 프레임을 처치 시각으로 보고, 아래 규칙의 시간을 게임 시계로 더해 계산한다. 일시정지 구간은 게임 시계가 멈추는 만큼 빼므로 타이머도 멈춘다.

규칙(패치 26.20, 2026 월드 챔피언십 패치. 26.1 이후 26.20 까지 오브젝트 규칙 변경은 없다):

| 오브젝트 | 규칙 | 근거 |
|---|---|---|
| 용 첫 등장 | 게임 시계 5:00 | 위키 Dragon pit, 26.1 노트("Epic Monster spawn times are unchanged") |
| 용 재등장 | 처치 5:00 뒤 | 위키 Dragon pit (V9.23) |
| 구덩이 원소 | 세 번째 용의 원소가 이후 모든 용의 원소 | 위키 Dragon pit (V9.23) |
| 용의 영혼 | 한 팀의 원소 용 4번째 처치 | 위키 Dragon pit |
| 장로 드래곤(엘더) | 4번째 용 처치 6:00 뒤, 엘더 처치 6:00 뒤마다 | 위키 Elder Dragon(Respawn 6:00), Dragon pit V14.3 |
| 바론 | 첫 등장 20:00, 처치 6:00 뒤 재등장 | 패치 26.1 노트("Baron Nashor: 25:00 ⇒ 20:00"), 위키 Baron Nashor |
| 아타칸 | 26.1 에서 삭제. 바론 시각에 영향을 주지 않는다 | 패치 26.1 노트 |

피드에는 용이 죽기 전의 원소가 없다. 다음 용의 원소는 세 번째 용을 잡은 뒤에야 보이고(`Infernal` 등), 한 팀이 용 3마리를 잡은 상태면 `Soul point` 가 붙는다.

검증: 규칙은 위키와 패치 노트에서 가져왔고 `objectives_test.go` 가 계산을 검사한다. 과거에 방송 6경기와 대조한 기록은 `.issueops/adr/2026-10-18-objective-timers.md` 에 있다.

한계
- 게임 중간에 라이브로 들어오면 그 전에 있었던 처치 시각을 모른다. 해당 구덩이는 `--` 로 표시되다가, 들어온 뒤 5분(바론·엘더는 6분)이 지나면 `UP` 이 되고, 새 처치를 보면 정확해진다. replay 는 게임 전체를 받는 중에 아직 받지 못한 구간에 처치가 있으면 같은 이유로 `--` 이다.
- 첫 용·첫 바론은 절대 게임 시계가 필요하다. 시계에 쓰는 피드 시차가 고정값(3.5초)이라 리그에 따라 최대 약 1.2초 어긋날 수 있다.

## 다시 보기 저장소

replay 는 끝난 게임의 프레임을 임의 접근할 수 있게 들고 있다(`replay_store.go`).

- livestats 피드는 프레임을 `startingTime` 으로 주소를 매긴 10초 창 단위로 준다. 창은 한 번만 받으므로 이동해도 요청이 반복되지 않는다.
- 재생 위치 주변 창(앞으로 3개)을 먼저 받고, 나머지 게임은 백그라운드에서 순서대로 받는다. 이 과정이 게임 일시정지도 드러낸다(게임 시계에 필요하다). 요청은 초당 4개로 늦춰 보드를 열자마자 피드를 몰아치지 않는다. 동시 요청은 4개다.
- 가장 최근에 연 3게임의 저장소는 보드를 닫아도 유지한다. 같은 게임을 다시 열면 요청이 없다.
- 프레임이 2초보다 길게 비는 구간에 걸친 킬은 시각을 알 수 없는 것으로 센다.

## 데이터 소스

| 엔드포인트 | 용도 |
|---|---|
| `esports-api.lolesports.com/persisted/gw/getLive` | 진행중 경기 + gameId |
| `.../getSchedule`, `/getLeagues`, `/getStandings` | 일정·결과·리그·순위 |
| `.../getEventDetails` | 경기의 세트 목록과 시리즈 점수, 방송 스트림 링크(`lol streams`) |
| `feed.lolesports.com/livestats/v1/window/{gameId}?startingTime=` | 팀 총합(킬/골드/용/바론/타워/억제기) + 선수 KDA/CS/체력 |
| `feed.lolesports.com/livestats/v1/details/{gameId}?startingTime=` | 선수별 아이템/데미지/시야 (상세) |

`window` 는 `startingTime`(10초 단위 정렬, RFC3339 ms) 파라미터가 있어야 그 시각부터 약 10초 분량
(실측 50~64프레임, 간격 불규칙)을 준다. 없으면 게임 스폰 시점 프레임만 리턴한다.
relay 는 처음에 현재 시각에서 10초 단위로 뒤로 내려가며 프레임이 있는 가장 최근 구간을 찾고, 그다음부터는
현재 구간을 2초마다 다시 받는다. 다음 구간은 현재 구간이 끝나기 약 2.5초 전부터 함께 요청해 구간 경계에서 멈추지 않게 한다.
3분 넘게 뒤처지면(절전 복귀 등) 다시 찾는다.

lolterm 은 이 피드에 있는 값만 보여 준다. 챔피언 위치, 텔레포트·귀환, 밴픽은 피드에 없으므로 보여 주지 않는다.

모든 시간은 KST 로 표시.
