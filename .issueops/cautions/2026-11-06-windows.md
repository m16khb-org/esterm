# Windows 네이티브 빌드: 콘솔 모드, 잡 객체, 명명된 파이프, 테스트 캐시 격리

- Date: 2026-11-06
- Kind: `caution`
- Source: cli
- Summary: lolterm 은 ioctl·termios·프로세스 그룹·fd 3/4 상속에 묶여 Windows 에서 빌드되지 않았다. 플랫폼 코드를 term_*.go·proc_*.go 로 나누고 Windows 쪽을 표준 라이브러리 syscall 과 kernel32 로 구현했다.
- Context: 사용자가 PowerShell 에서 go build 했을 때 minimap_kitty.go 의 syscall.SYS_IOCTL 등으로 실패했다. os/exec 의 ExtraFiles 는 Windows 에서 지원되지 않아 메인 뷰 fd 4 파이프도 쓸 수 없다. WSL 에서 Linux 빌드가 Windows ffmpeg.exe 를 부르면 fd 4 가 전달되지 않아 레이아웃이 잠기지 않았다(같은 Linux 빌드에 Linux ffmpeg 이면 정상). 테스트가 HOME·XDG_CACHE_HOME 만 바꿔서 Windows 에서는 os.UserCacheDir(%LocalAppData%) 에 가짜 아이콘을 남겼고, 다음 테스트가 그 캐시를 읽어 실패했다.
- Resolution: term_windows.go: 시작할 때 stdout/stderr 에 ENABLE_VIRTUAL_TERMINAL_PROCESSING, raw 모드는 줄 입력·에코·Ctrl+C 처리·빠른 편집을 끄고 ENABLE_VIRTUAL_TERMINAL_INPUT 을 켠다(키·마우스가 유닉스와 같은 이스케이프로 온다). 터미널 질의(ttyQuery)는 콘솔 입력에 시간 제한 읽기가 없어 하지 않는다. proc_windows.go: 자식마다 KILL_ON_JOB_CLOSE 잡 객체에 넣어 lolterm 이 강제 종료돼도 ffmpeg·yt-dlp(pip 런처가 띄운 python 포함)가 함께 죽는다. 메인 뷰는 \\.\pipe\lolterm-main-<pid>-<n> 명명된 파이프를 ffmpeg 출력 파일로 주고(-y), ffmpeg 가 열기 전에 끝나면 Close 가 직접 열어 대기 중인 ConnectNamedPipe 를 풀어 준다. 셸 스크립트 대역이나 프로세스 그룹을 쓰는 테스트는 *_unix_test.go 로 옮겼고, 캐시 격리는 isolateCache(HOME, XDG_CACHE_HOME, LocalAppData) 로 통일했다. 확인: Windows 에서 go vet·go test 통과, 대화형 앱 키 입력과 q 종료, minimap CLI(메인 뷰 100프레임 중 36프레임 수신), Stop-Process -Force 뒤 ffmpeg 0개. WSL Linux 에서 go test -race 통과.
