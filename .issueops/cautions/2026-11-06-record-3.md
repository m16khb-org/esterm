# 전체 화면 루프는 닫힌 키 채널과 터미널 없는 실행을 직접 막아야 한다

- Date: 2026-11-06
- Kind: `caution`
- Source: cli
- Summary: stdin 이 EOF 면 키 채널이 닫혀 relay·replay·minimap 보드 루프가 0값 키를 무한히 받아 전체 다시 그리기를 반복했다(초당 수십 MB 출력, 종료 불가). 터미널 없이 시작하면 대체 화면과 raw 모드도 실패를 무시하고 진행했다.
- Context: 릴리스 전 감사에서 'lolterm lol relay < /dev/null' 이 4초에 252 MB 를 쓰고 끝나지 않았다. app.go 만 'case k, ok := <-keys' 로 막고 있었다. 백그라운드 고루틴의 panic 은 메인 고루틴의 defer 를 건너뛰어 터미널을 대체 화면·raw 모드로 남겼다.
- Resolution: 세 보드 루프가 ok 를 확인한다(relay·replay 는 종료, minimap 패널은 keys=nil 로 파이프라인 결과를 기다림). enterFullscreenMode 는 stdin·stdout 이 터미널이 아니거나 makeRaw 가 실패하면 stop 후 오류로 종료한다(한 프레임은 relay -1). 백그라운드 고루틴은 defer crashGuard() 로 터미널을 복구한 뒤 다시 panic 한다. 키 입력마다 prev=nil 로 전체 다시 그리던 것은 Ctrl+L 에만 남겼다(kitty 지도 재전송 약 100 KB 방지). 새 전체 화면 루프나 고루틴을 추가할 때 같은 세 가지를 지킨다.
