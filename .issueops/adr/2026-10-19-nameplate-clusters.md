# 메인 뷰 이름표는 글자로 읽지 않고 모양으로 묶어 투표로 챔피언에 잇는다

- Date: 2026-10-19
- Kind: `adr`
- Source: cli
- Summary: 체력바 위 이름표를 팀 색별 모양 묶음(상관 0.88)으로 모으고, 묶음에 들어온 체력바의 레벨·체력·위치 일치를 표로 세어 챔피언에 잇는다(mainview_plate.go). 확정된 이름표는 mvAssign에서 다른 챔피언의 배정 비용을 3.0 올리고 그 챔피언의 마지막 위치 조건을 끈다.
- Context: 메인 뷰 체력바 배정은 레벨·체력·마지막 위치만 썼다. 같은 레벨에 체력이 비슷한 챔피언(원딜·서포터, 아군에 붙은 Yuumi)을 헷갈렸고, 눈으로 읽은 체력바 182개에서 배정된 것 중 틀린 비율이 6.6%, 배정 못한 비율이 6.6%였다. 이름표는 방송마다 글꼴이 다르고 이름 문자열만 알아 글자 템플릿을 미리 만들 수 없다.
- Decision: 이름표 창(152x22 px)을 체력바 왼쪽 위에서 잘라 팀 색별 묶음 14개 안에서 상관(몇 픽셀 이동 허용)으로 찾고, 0.88 이상이면 묶음에 평균해 넣고 아니면 새 묶음을 만든다. 묶음마다 2초에 한 번, 들어온 체력바가 레벨·체력(0.04 이내)·마지막 위치(2.5초 이내)와 맞는 챔피언에게 표를 준다. 표 30개 이상에 1등이 2등을 표당 0.5 넘게 앞서면 그 묶음이 그 챔피언의 이름표다. 투표는 배정 결과를 쓰지 않는다. 기각한 대안: (1) 레벨이 하나뿐인 체력바로 챔피언별 기준 그림을 만드는 방식은 레벨이 가까운 챔피언(원딜·서포터)이 배울 기회가 적고, 확신도 기준으로 가르치면 서로 이름표를 바꿔 배웠다. (2) 상관 임계값 0.7은 Zeus와 Zeka처럼 두 글자만 다른 이름을 한 묶음으로 합쳤다. (3) 이름 문자열에서 글자 템플릿을 만드는 방식은 글꼴 4종의 글리프를 줄 방법이 없어 하지 않았다.
- Consequences: 5경기 182개 대조: 배정된 체력바 중 맞은 비율 86.8%에서 97.3%, 틀린 5개는 모두 게임 시작 후 3분 안(확정 전). 메인 뷰가 메우는 공백 비율 17.0%에서 24.4%, 생존 검출 92.7%에서 93.3%, 5초 넘는 공백 457건에서 431건. 메인 뷰 비용은 프레임당 2.6~4.0 ms 늘었다. 이름표는 게임마다 새로 배우므로 확정까지 챔피언당 약 1분어치 표가 필요하고, 챔피언 고유의 상태 문구(Vi의 CHANNELING)는 그 챔피언의 이름표로 확정되기도 한다. 근거: mainview_plate.go, mainview_map.go, README 메인 뷰 이름표 절.
